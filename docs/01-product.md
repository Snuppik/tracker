# 01. Продукт: что именно мы делаем

## 1. Одна фраза

**Tracker** — веб-приложение личного списка задач: пользователь регистрируется, заводит задачи с дедлайном и приоритетом, перетаскивает их по доске `todo → in_progress → done`, ставит себе напоминание и получает пуш в браузер, а «умные подсказки» подсвечивают перегрузку и горящие задачи.

## 2. Пользователь и проблема

Один человек, который ведёт дела в переписке/голове/заметках и из-за этого срывает сроки. Ему нужно:
1. быстро выгрузить всё в один список;
2. видеть, что горит сегодня;
3. не забыть про задачу с конкретным дедлайном (отсюда напоминание);
4. понимать, что план на день нереалистичен (отсюда rule-based подсказки).

Всё остальное — команды, проекты, интеграции — в скоуп не входит (`00-decisions.md` §1).

## 3. Пользовательские истории (MVP = все Must закрыты)

### Must

| ID | История | Критерий приёмки |
|---|---|---|
| M-1 | Как гость, я могу зарегистрироваться по email и паролю, чтобы у моих задач был владелец | `POST /api/auth/register` создаёт пользователя, ставит cookie, редирект на доску; повторный email → `409` |
| M-2 | Как пользователь, я могу войти и выйти | `POST /api/auth/login` → cookie; `POST /api/auth/logout` → cookie сброшен; без cookie любая `/api/*` (кроме auth-эндпоинтов и `/healthz`) → `401` |
| M-3 | Как пользователь, я не вижу чужие задачи | Второй аккаунт с тем же ID задачи в URL → `404`, а не чужие данные |
| M-4 | Как пользователь, я могу создать задачу: название, описание, приоритет, дедлайн | `POST /api/tasks`; название обязательное, ≤200 символов; пустое название → `400` с `details` |
| M-5 | Как пользователь, я могу изменить и удалить задачу | `PATCH /api/tasks/{id}`; `DELETE /api/tasks/{id}` с подтверждением в UI; каскадно удаляются напоминания |
| M-6 | Как пользователь, я могу менять статус задачи | `PUT /api/tasks/{id}/status`; недопустимое значение → `400`; на доске — перетаскиванием карточки между колонками |
| M-7 | Как пользователь, я могу смотреть задачи на kanban-доске | 3 колонки, карточка: название, приоритет (цвет), дедлайн, счётчик напоминаний, просроченность |
| M-8 | Как пользователь, я могу смотреть задачи списком | Таблица/список с той же карточкой-деталью, сортировка по дедлайну/приоритету/дате создания |
| M-9 | Как пользователь, я могу фильтровать и искать | Фильтр по статусу, фильтру по приоритету, текстовый поиск по названию; всё сервером через query-параметры, состояния фильтров сохраняются в URL |
| M-10 | Как пользователь, я вижу просроченные и «горящие» задачи | Просроченная (`due_at < now`, статус ≠ `done`) — красный бейдж; горящая (`now < due_at ≤ now+24h`) — оранжевый |
| M-11 | Как пользователь, я могу создать напоминание к своей задаче | Внутри детали задачи: `datetime-local` + текст ≤200 символов; только в будущем; ≤5 напоминаний на задачу |
| M-12 | Как пользователь, я получаю уведомление, когда напоминание наступает | В течение ≤60 секунд после `fire_at`: запись в колокольчике + (если оформлена push-подписка) системное пуш-уведомление браузера с названием задачи |
| M-13 | Как пользователь, я вижу счётчик непрочитанных уведомлений | Красный бейдж на колокольчике, обновление ≤30 с; «прочитать все» одной кнопкой |
| M-14 | Как пользователь, я вижу мини-дашборд | 4 числа: всего активных / в работе / готово за 7 дней / просрочено. Сходится с реальным содержимым БД |
| M-15 | Как пользователь, я вижу умные подсказки | Блок «Аналитика» с 0–5 подсказками, у каждой причина и кнопка «показать задачи» |
| M-16 | Как участник, я запускаю проект одной командой | `docker compose up -d` → через ~30 с `http://localhost:8080` отдаёт приложение, `/healthz` = `ok` |

## 4. Функциональная карта экранов

```
/login          форма входа + ссылка на регистрацию
/               (index.html) — требует авторизации, иначе редирект на /login
  ├ шапка: логотип · переключатель вид kanban/список · поиск · колокольчик(бейдж) · меню пользователя (Выйти)
  ├ панель «Аналитика»: счётчики M-14 + подсказки M-15
  ├ основная область: kanban-доска (3 колонки) ИЛИ список
  ├ модалка «Задача»: создание/редактирование + вкладка «Напоминания»
  └ модалка «Уведомления»: лента + «прочитать все»
```

Три состояния каждого экрана: загрузка (скелетон), ошибка (текст + «повторить»), пусто (подсказка + действие). Это часть приёмки, а не «полировка».

## 5. Критерии приёмки финального MVP (проверяются по порядку на демо)

1. Чистый `git clone` → `docker compose up -d` → `http://localhost:8080` открывает страницу входа.
2. Регистрация нового пользователя → авто-вход → пустая доска с подсказкой-онбордингом.
3. Создание 5 задач с разными приоритетами и дедлайнами (в т.ч. одна просроченная, одна через 2 часа) — все видны на доске в колонке `todo`.
4. Перенос карточки `todo → in_progress` мышью → перезагрузка страницы (F5) → карточка осталась в `in_progress`. **Это главный тест персистентности.**
5. Переключение на список → фильтр «высокий приоритет» → поиск по подстроке → счётчик результатов сходится.
6. Просроченная задача подсвечена красным, «горящая» — оранжевым.
7. У задачи создан напоминание на `now + 1 мин` → через минуту появляется всплывающее системное уведомление браузера (или, если пуш недоступен, запись в колокольчике с unread-бейджем).
8. Блок «Аналитика» выдаёт осмысленную подсказку («3 задачи горят в ближайшие 24 часа»).
9. Выход → вход под вторым аккаунтом → список задач пуст, чужие задачи недоступны даже по прямому URL `/api/tasks/{id}`.
10. `go test ./...` зелёные; `gofmt -l .` пуст; `go vet ./...` без замечаний.

## 6. Что демонстрируем в 4-минутном питче

Порядок и текст — в `10-demo-script.md`. Ключевые сообщения для IT-компании:
- не «ещё один to-do», а **замкнутый цикл: задача → дедлайн → напоминание → пуш → аналитика**;
- честный стек без раздувания: Go 1.27 stdlib-роутинг, 5 внешних зависимостей, 0 сборщиков на фронте;
- воспроизводимость подсказок: детерминированные правила вместо «чёрного ящика», который на демо молчит.
