# 00. Зафиксированные решения

Документ — единственный источник истины по решениям продукта и стека.
Любое отступление от таблиц ниже требует явного согласования всей командой и обновления этого файла.

Дата фиксации: 2026-10-26. Команда: 3 человека. Срок: 4 дня. Формат сдачи: живое демо на хакатоне перед IT-компанией.

---

## 1. Продуктовые решения

| # | Решение | Выбрано | Обоснование | Отклонено |
|---|---|---|---|---|
| P-1 | Модель доступа | **Личный трекер: каждый пользователь видит только свои задачи** | Даёт «взрослый» вид продукта и изоляцию данных ценой одной колонки `user_id`. Команда из 3 человек не успевает сделать совместную работу с проектами за 4 дня | (A) без авторизации вообще — нечем показать изоляцию данных, жюри увидит «болванку»; (C) командный трекер с проектами, участниками, ролями, назначением задач — оценка выполнимости ~35%, гарантированный недодел |
| P-2 | Напоминания | **Пользователь сам создаёт напоминание внутри задачи; доставка — пуш на того же пользователя, который создал задачу** | Прямое требование заказчика. В модели P-1 автор задачи = владелец задачи, поэтому адресация «по user_id» тривиальна | Назначение напоминания другому человеку (нет P-2 в командной модели), email, SMS |
| P-3 | Статусы задачи | **Ровно 3: `todo` / `in_progress` / `done`** | Три колонки = kanban без прокрутки; меньше веток в валидации, UI и тестах | 4-й статус `blocked` — раздувает UX и тесты без пользы для демо |
| P-4 | Приоритет | **Enum `low` / `medium` / `high`** | Читается в UI без легенды, сортируется, валидируется одной строкой | Числовой приоритет 1–9 — требует объяснения пользователю |
| P-5 | Представление задач | **Два вида: kanban (drag&drop) и список** | Kanban — демо-визуал, список — рабочая лошадка с фильтрами. Оба на одном состоянии | Только kanban (неудобно фильтровать), только список (нет «вау») |
| P-6 | Drag & drop | **Да, на natивном HTML5 DnD** | Ключевой интерактив для презентации. Нулевая зависимость | Сторонние lib (SortableJS) — dependency + разбор API; только кнопки — скучно на демо |
| P-7 | Источник данных на демо | **Пользовательские данные: демо-аккаунт заполняется руками в ходе презентации** | Требование заказчика: оцениваем функционал, а не заготовку | Seed-скрипт на 15 задач — «подкрученное» демо, жюри это видит |
| P-8 | Язык интерфейса | **Только русский** | Аудитория русскоязычная | i18n/переключатель языков — +полдня ради нуля пользы |

### Что явно вычеркнуто из скоупа (не делать, даже если останется время)

Комментарии, вложения, подзадачи, чек-листы внутри задачи, повторяющиеся задачи (recurrence),
история изменений (audit log), совместное редактирование, realtime-синхронизация между вкладками (WebSocket/SSE),
email-рассылки, календарь, экспорт/импорт, мобильное приложение, интеграции (Telegram/Google Calendar),
пользовательские статусы, теги и категории, тёмная тема как самостоятельная фича (остаётся в should-have — см. `01-product.md` S-1).

Любая из этих фич = красный флаг. Если AI-агент предлагает её «добить» — ответ: нет, см. `AGENTS.md` §7.

## 2. Технические решения

| # | Область | Решение | Обоснование |
|---|---|---|---|
| T-1 | Язык/рантайм | **Go 1.27** | Требование заказчика. В 1.27 в stdlib появился пакет `uuid` (`uuid.NewV7()` — time-sortable), `encoding/json` работает на новой реализации v2, поддерживаются generic methods. В окружении сейчас Go 1.18.1 — обновить обязательно (см. `09-devops.md`) |
| T-2 | HTTP-роутер | **`net/http` + `http.ServeMux` с паттернами Go 1.22+ (`"GET /api/tasks/{id}"`)** | Покрывает весь CRUD без единой зависимости. `chi` разрешён как явная альтернатива, если команде так привычнее, — это ~30 минут на замену, но не смешивать два роутера в одном проекте |
| T-3 | API-протокол | **REST + JSON** | Браузер не умеет gRPC без Envoy + buf + protoc + grpc-web. На 4 дня это +1 день инфраструктуры при нулевой пользовательской пользе. Плюс OpenAPI-спека = готовый контракт для параллельной работы фронта и бэка |
| T-4 | База данных | **PostgreSQL 16 в Docker** | Требование заказчика. Одна живая БД на троих, миграции, «серьёзный» вид. `psql` 14.24 в окружении — клиент, сервер поднимется контейнером |
| T-5 | Драйвер | **`github.com/jackc/pgx/v5/stdlib` через интерфейс `database/sql`** | pgx — стандарт для Postgres; обёртка `stdlib` даёт привычный `database/sql`: `Scan` в `string`/`time.Time` без вопросов о кодеках типов, простые транзакции, меньше pgx-специфики для двух участников, не пишущих на Go |
| T-6 | Миграции | **Один идемпотентный `db/schema.sql`, загружаемый через `go:embed` и выполняемый при старте** | `CREATE TABLE IF NOT EXISTS` + `CREATE INDEX IF NOT EXISTS`. За 4 дня это дешевле и безопаснее, чем goose/migrate: нет отдельного CLI, нет состояния таблицы `schema_migrations`, нет рассинхрона у троих |
| T-7 | Идентификаторы | **`uuid` в Postgres; в Go — `string`, генерация `uuid.NewV7().String()` из stdlib** | UUID v7 сортируются по времени (удобно для пагинации/отладки). Держим ID в моделях как `string`: нет зависимости `google/uuid`, нет вопросов о маршалинге, JSON-контракт очевиден |
| T-8 | Типы перечислений | **`text` + `CHECK` вместо `CREATE TYPE ... AS ENUM`** | `ALTER TYPE` — дорогая и ломкая операция (нельзя удалить значение, нужны `RENAME`-трюки). CHECK меняется переопределением констрейнта и одинаково работает в тестах |
| T-9 | Авторизация | **JWT (HS256) в cookie `tracker_session`, флаги `HttpOnly` + `SameSite=Lax` + `Path=/`** | Токен не читается JS → нет кражи через XSS, фронт не пишет хранилище токена, нет ручного заголовка в `fetch` (`credentials: 'same-origin'` достаточно). Сессии в памяти отклонены: при рестарте API все залогиненные вылетают, а на демо API перезапускается часто |
| T-10 | Хэширование паролей | **`golang.org/x/crypto/bcrypt`, cost 10** | Де-факто стандарт, одна строка. Argon2id — избыточно для MVP |
| T-11 | Раздача фронта | **Статика отдаёт тот же Go-процесс (`http.FileServerFS`)** | Один порт, один origin → CORS не нужен вообще, `sw.js` получает scope `/` (Web Push этого требует), демо = один процесс. Плюс `no-cache` для HTML и `immutable` для `/css`, `/js` |
| T-12 | Сборщик фронта | **Нет. Vanilla HTML + CSS + ES-модули** | Требование заказчика, и оно правильное: Node в окружении нет, и мы его не ставим. Только нативные браузерные API |
| T-13 | CSS-фреймворки | **Нет. Свои дизайн-токены на CSS custom properties** | Tailwind через CDN падает без сети и весит ~400 КБ ради utility-классов, которые руками пишутся за то же время |
| T-14 | Уведомления | **Двухуровневые: in-app (must) + Web Push VAPID (should)** | См. §3 «Ограничение Web Push». In-app работает при любых условиях и спасает демо |
| T-15 | AI | **Только rule-based подсказки, детерминированные на сервере** | Требование заказчика. Не нужен API-ключ, не падает без сети, результат воспроизводим и показывается по запросу «почему такая подсказка» — на защите это плюс, а не минус |
| T-16 | Конфигурация | **env-переменные + `github.com/joho/godotenv` для локальной разработки** | 12 Factor, ничего лишнего. Конфиг-файлы и флаги отклонены |
| T-17 | Логи | **`log/slog` (stdlib, JSON в проде, text в dev)** | Без зависимостей |
| T-18 | Валидация | **Вручную в слое `service`, ~20 строк на сущность** | `go-playground/validator` — reflection, теги в моделях, ещё одна идеоматика для двух фронтендеров, пишущих Go-код через агентов |
| T-19 | Docker | **`docker-compose.yml`: сервисы `postgres` + `api`** | Требование заказчика. `docker compose` v2 plugin в окружении отсутствует — доставить |
| T-20 | Тесты | **`httptest` + stdlib `testing`, 8–12 кейсов на task/reminder-хендлеры** | Проверяемые критерии приёмки; без testify и моков БД (используем реальный Postgres из compose в CI-локальном прогоне) |
| T-21 | Git-процесс | **Прямые пуши в `main`, ревью — глазами соседа до пуша** | Решение заказчика. Компенсация: обязательный зелёный `go build ./... && go test ./...` перед пушем (см. `AGENTS.md` §6) |
| T-22 | Репозиторий | **Один общий репозиторий на троих** | Монополия на контракт: `api/openapi.yaml` живёт там же |
| T-23 | Рабочее расположение | **Рекомендуется клонировать внутрь WSL (`~/projects/tracker`), а не в `/mnt/d/tracker`** | `/mnt/d` — Windows-диск через 9p/drvfs: metadata-операции и `go build` заметно медленнее, плюс конфликты CRLF. Если команда решает оставить `/mnt/d` — принять как данность и настроить `.gitattributes` |

## 3. Критическое ограничение Web Push (прочитать всем)

Web Push зарегистрирован только в **secure context**. Практически это значит:

| Where | Push работает? |
|---|---|
| `http://localhost:8080`, `http://127.0.0.1:8080` | **Да** (Chrome, Edge, Firefox) |
| `https://…` | Да |
| `http://192.168.x.x:8080` (доступ с чужого ноутбука по Wi-Fi) | **Нет.** `PushManager` отсутствует, подписка невозможна |
| Safari на iOS | Только если PWA добавлено на домашний экран (iOS 16.4+) |
| Linux без notification daemon | Штатного всплывающего окна может не быть |

**Вывод для демо:** выступать на машине, где открыт `http://localhost:8080`. Если нужен доступ с другого устройства — либо HTTPS через `mkcert`, либо показываем in-app-уведомления.
Дизайн двухуровневых уведомлений (in-app как must-have, Web Push как надстройка поверх одного и того же источника событий) описан в `06-reminders-push.md`.

## 4. Принятые риски (осознанно, а не «авось»)

| Риск | Вероятность | Компенсация |
|---|---|---|
| Напоминания + планировщик + Web Push — это ~1.5 чел-дня бэкенда из 4 | Высокая | Order of sacrifice зафиксирован: при отставании **режем Web Push, оставляя in-app**. Ядро (auth + CRUD + kanban) не режем ни при каких условиях |
| Go 1.18.1 в окружении vs требуемая 1.27 | 100% сейчас | Установка Go 1.27 — задача №0 дня 1, блокер для всех |
| `docker compose` plugin отсутствует | 100% сейчас | Установка — задача №0. План Б: локальный `initdb` + `pg_ctl`, API вне Docker |
| Один backend-человек — единая точка отказа | Высокая | Контракт `api/openapi.yaml` + mock-данные к концу дня 1, чтобы фронт не простаивал. Фронтендеры при необходимости пишут Go-код через AI-агента по шаблонам `internal/` |
| Drag&Drop на HTML5 DnD капризен (Firefox, touch) | Средняя | Обязательный запасной путь: `select` со статусом на карточке. DnD — улучшение, а не единственный способ |
| Жюри просит «показать, что данные не подставные» | Средняя | Демо заполняется вживую руками (P-7), БД — реальная, без seed-скрипта |

## 5. Что запрещено менять без пересмотра этого документа

- Список зависимостей Go (см. `AGENTS.md` §4) — только по явному решению.
- Количество статусов и значений приоритета (они зашиты в CHECK-констрейнты, UI, фильтры, тесты, инсайты).
- REST вместо gRPC.
- Правило «запрос всегда скопирован по `user_id` из токена, а не из тела запроса» — это вопрос безопасности, не удобства.
