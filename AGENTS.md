# AGENTS.md — Правила для AI-агентов

Этот файл — главный контракт между командой и AI-агентом. Все агенты (включая меня) обязаны следовать этим правилам.

## 0. Контекст проекта

- **Название:** Tracker
- **Тип:** Веб-приложение личного трекера задач (MVP, хакатон, 4 дня)
- **Команда:** 3 человека (1 backend, 2 frontend+дизайнер)
- **Формат сдачи:** живое демо на хакатоне перед IT-компанией
- **Язык интерфейса:** русский
- **Язык комментариев в коде:** русский (идентификаторы — на английском)
- **Язык документации:** русский

## 1. Порядок чтения

Перед любой работой агент обязан прочитать:

1. `AGENTS.md` ← вы здесь
2. `docs/00-decisions.md` — зафиксированные решения (продуктовые и технические)
3. `api/openapi.yaml` — контракт API (машина-читаемый)
4. `docs/04-api.md` — пояснение к контракту
5. `docs/03-data-model.md` — модель данных
6. `docs/02-architecture.md` — архитектура

Если один из файлов отсутствует — **не продолжать**, запросить его у пользователя.

## 2. Запрет на домысливание

**Агент НЕ ДОЛЖЕН:**
- Изменять количество статусов (`todo/in_progress/done`) или приоритетов (`low/medium/high`).
- Добавлять новые эндпоинты, поля, таблицы или типы без явного указания.
- Удалять существующие эндпоинты или поля.
- Менять язык интерфейса или добавлять i18n.
- Заменять REST на gRPC.
- Заменять PostgreSQL на SQLite.
- Добавлять новые зависимости в `go.mod` без явного указания.
- Добавлять фреймворки на фронтенд (React, Vue, Svelte и т.д.).
- Добавлять сборщики (Vite, webpack, esbuild и т.д.).
- Добавлять CSS-фреймворки (Tailwind, Bootstrap и т.д.).
- Добавлять ORM (GORM, sqlx, sqlc).
- Добавлять очереди задач, Redis, Kafka.
- Добавлять WebSocket, SSE.
- Добавлять email/SMS/Telegram.
- Добавлять кэширование.
- Добавлять аналитику (PostHog, GA).
- Добавлять «улучшения» в код, который не был изменён.

**Агент ДОЛЖЕН:**
- Следовать контракту `api/openapi.yaml` как источнику истины.
- Использовать только технологии, зафиксированные в `00-decisions.md`.
- Использовать `docs/` как источник контекста, а не додумывать архитектуру.
- Если контракт неоднозначен → задать вопрос, а не выбирать «на своё усмотрение».
- Если правило противоречиво → указать конфликт и запросить решение.

## 3. Область владения

Каждый файл имеет «хозяина». Агент может редактировать файл только если:

| Пакет / Файл | Владелец |
|---|---|
| `internal/` (backend Go) | Backend-разработчик (или агент по его указанию) |
| `api/openapi.yaml` | Backend-разработчик (или агент по его указанию) |
| `db/schema.sql` | Backend-разработчик (или агент по его указанию) |
| `cmd/` | Backend-разработчик |
| `web/js/api.js`, `state.js`, `ui.js`, `router.js`, `kanban.js`, `task-modal.js`, `reminders.js`, `app.js` | FE1 (логика) |
| `web/js/list.js`, `dashboard.js`, `insights.js`, `notifications.js` | FE2 (представление) |
| `web/css/` | FE2 (дизайн) |
| `web/*.html` | FE2 (структура) |
| `web/sw.js` | FE1 + FE2 совместно (уведомления) |
| `docs/` | Вся команда |
| `docker-compose.yml` | Backend |
| `Dockerfile` | Backend |
| `.env.example` | Backend |
| `.gitignore`, `.gitattributes`, `.editorconfig`, `Makefile` | Вся команда (по согласованию) |
| `AGENTS.md`, `README.md` | Вся команда (по согласованию) |

**Правило:** если задача требует изменения файлов из чужой области — агент должен упомянуть это в отчёте и попросить подтверждение у пользователя.

## 4. Стек и зависимости

### Go

```
module tracker
go 1.27
```

**Разрешённые зависимости (белый список):**

| Пакет | Назначение |
|---|---|
| `github.com/jackc/pgx/v5/stdlib` | Postgres-драйвер (через database/sql) |
| `golang.org/x/crypto/bcrypt` | Хэширование паролей |
| `github.com/golang-jwt/jwt/v5` | JWT-токены |
| `github.com/SherClockHolmes/webpush-go` | Web Push VAPID |
| `github.com/joho/godotenv` | Локальная загрузка .env |

**Максимум 5 прямых зависимостей.** Любая новая зависимость = блокировка до явного согласия пользователя.

**Правила Go:**
- `CGO_ENABLED=0` для сборки.
- Только `database/sql` поверх pgx, не pgx-native.
- `log/slog` (stdlib) для логов.
- `net/http` + `http.ServeMux` (Go 1.22+ паттерны) для роутинга.
- `go:embed` для схемы и статики.
- `uuid.NewV7().String()` из stdlib `uuid` (Go 1.27).
- Никакого `panic` в бизнес-логике. Ошибки возвращаются.
- Никаких глобальных переменных.
- Контекст `context.Context` — обязательный первый параметр всех DB-операций.
- `defer` для `rows.Close()`, `tx.Rollback()`, `ticker.Stop()`.
- `fmt.Errorf` вместо `errors.New` с причиной. `errors.Is` для сравнения.

### JavaScript (фронтенд)

- ES-модули (`<script type="module">`).
- `fetch` с `credentials: 'same-origin'`.
- Никаких `eval`, `new Function`, `innerHTML` с пользовательскими данными.
- Все пользовательские строки в DOM — через `textContent` или `esc()`.
- `structuredClone` для копирования состояния.
- `Intl.DateTimeFormat` для дат (русская локаль).
- Нативный `<dialog>` для модалок.
- Нативный HTML5 DnD (`draggable`, `dragstart`, `drop`).
- `navigator.serviceWorker.register`, `PushManager`.
- `document.visibilitychange` для паузы polling.

### CSS

- CSS Custom Properties (`var(--...)`) как единственный источник значений.
- Семантические имена (`--c-danger`, `--s-4`), не сырьё (`--color-red: #f00`).
- BEM-подобные имена: `.card-title`, `.btn-icon`, `.column-body`.
- `:focus-visible` на всех интерактивных элементах.
- Медиа-запросы: `@media (min-width: 768px)` и `@media (min-width: 1200px)`.
- Анимации только `transition` (без `@keyframes`, если нет веской причины).

## 5. Контракт API

`api/openapi.yaml` — источник истины.

**Правила:**
1. Если хендлер не описан в `openapi.yaml` → агент не должен его добавлять.
2. Если в коде есть эндпоинт, которого нет в `openapi.yaml` → агент обязан добавить его в спецификацию.
3. Изменение контракта → правка `openapi.yaml` **в том же коммите**, что и код.
4. Все ответы `/api/*` — `Cache-Control: no-store`.
5. Ошибки — формат `{"error":{"code":"...", "message":"...", "details":[...]}}`.
6. Коды ошибок: 400 validation, 401 unauthorized, 404 not_found, 409 conflict, 422 limit_exceeded, 500 internal.

## 6. Безопасность (жесткие правила)

Каждый раз, когда код затрагивает безопасность, агент обязан:

1. **Скоуп по `user_id`.** Каждый запрос к `tasks`, `reminders`, `notifications`, `push_subscriptions` содержит `WHERE user_id = $1`. Значение берётся из JWT-контекста, а не из тела запроса или URL-параметра.
2. **Не доверять клиенту.** `user_id` никогда не берётся из `POST /api/tasks/{id}`, `PATCH /api/tasks/{id}`, `PUT /api/tasks/{id}/status`. Если хендлер получает `task_id` из URL — он всегда должен проверять `WHERE id = $1 AND user_id = $2`.
3. **Пароли.** Только `bcrypt`. Никогда не возвращать `password_hash` в ответах.
4. **Cookie.** `HttpOnly`, `SameSite=Lax`, `Path=/`, `Secure` зависит от `ENV` (или `COOKIE_SECURE`).
5. **JWT.** HS256, секрет из env. Битый/просроченный → `401 unauthorized`.
6. **SQL-инъекции.** Только параметризованные запросы `$1, $2, ...`. Никакой `fmt.Sprintf` для вставки пользовательских данных в SQL.
7. **XSS.** `innerHTML` без `esc()` = нарушение. Все пользовательские данные в DOM → `esc()` или `textContent`.
8. **Секреты в git.** `.env`, `.env.local`, `*.pem` — в `.gitignore`. Никогда не коммитить ключи.

## 7. Definition of Done для каждого изменения

Каждое изменение кода считается закреплённым только если:

- [ ] Код скомпилируется: `go build ./...`
- [ ] Тесты проходят: `go test ./...` (или подтверждение, что тестов нет)
- [ ] Форматирование: `gofmt -l .` пуст
- [ ] Ветеринария: `go vet ./...` без замечаний
- [ ] Новый код не добавляет зависимостей в `go.mod` (без согласия)
- [ ] Новые эндпоинты добавлены в `api/openapi.yaml`
- [ ] Новые поля в ответах согласованы с `openapi.yaml`
- [ ] Документация (`docs/`) обновлена, если изменилась архитектура или API

## 8. Что агент НЕ должен делать (жесткий запрет)

- **Не удалять код** без явного указания «удалить». Если код устарел — пометить `// TODO: remove` и сообщить пользователю.
- **Не изменять `.gitignore`**, `.editorconfig`, `.gitattributes` без прямого запроса.
- **Не запускать `git`-команды** (commit, push, merge, rebase, reset) без прямого запроса.
- **Не устанавливать пакеты** (`go install`, `npm install`, `apt-get`) без прямого запроса.
- **Не изменять `docker-compose.yml`** без прямого запроса (это инфраструктурный файл).
- **Не менять `db/schema.sql`** без прямого запроса (это влияет на всех троих разработчиков).
- **Не менять `openapi.yaml`** без прямого запроса (это контракт).
- **Не «улучшать» код** рядом с изменённым (принцип хирургической точности).
- **Не добавлять комментарии** вида «/* TODO: refactor */» в новый код.
- **Не добавлять `fmt.Println`** в продакшен-код (использовать `slog`).
- **Не использовать `time.Now()`** в тестовых данных без явного указания (использовать фиксированные даты).
- **Не использовать `database/sql`/`pgx` напрямую** — только через `database/sql` интерфейс (T-5).

После выполнения задачи агент обязан сообщить:

```

  - Файл1: краткое описание изменений
  - Файл2: ...

📝 Внесённые изменения:
  - api/openapi.yaml: (если менялся)
  - docs/: (если менялись)
  - go.mod: (если менялись зависимости)

🔍 Проверки:
  - go build ./...: OK / FAIL
  - go test ./...: OK / FAIL (или N/A)
  - gofmt: OK / FAIL
  - go vet: OK / FAIL

⚠️ Отклонения:
  - (если что-то не соответствует контракту, описать)
```

Если что-то не сработало — честно сообщить и предложить альтернативу.

## 11. Поведение при неопределённости

Если запрос пользователя противоречит документации:

1. Указать на конкретное противоречие.
2. Предложить решение, которое минимально затрагивает текущий скоуп.
3. Запросить подтверждение.
4. Если пользователь настаивает — выполнить, но пометить в отчёте как «отклонение от контракта».

Если запрос слишком абстрактен («сделай красиво», «сделай профессионально») — уточнить:

> ««Красиво» — это: добавить тёмную тему? Улучшить анимации? Добавить валидацию? Конкретизируйте, пожалуйста, чтобы я не додумывал лишнее.»

Если запрос требует действия, выходящего за рамки разрешённых (инсталляция, git, docker-compose изменение) — запросить подтверждение.
